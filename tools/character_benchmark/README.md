# Character Benchmark 1.0

本目录只增加评测，不修改生产代码、prompt、人格或既有工程评分。30+ 固定场景组成 10 个 3–10 步序列，每个序列从空白会话重复运行 3 次；序列内状态持续。准确场景数由冻结协议记录。

运行（使用已安装项目依赖的 Python）：

```powershell
python tools/character_benchmark/run.py prepare
python tools/character_benchmark/run.py generate
python tools/character_benchmark/run.py judge
python tools/character_benchmark/run.py report
```

生成模型沿用 `.env` 的配置。独立裁判默认 `gpt-5.5`，通过 `--judge-model` 在 prepare 前选择。不会记录密钥。先检查协议再运行；断点续跑不重复已成功完成的候选。传输错误会停止，不能用假回应或零分补齐基线。普通 unittest 不调用真实 API。

## 测量边界

- `observe` 场景将合成截图送入现有 ObserveWorker、观察记忆、人格边界、回复去重、发言节奏及 OverlayApp 展示链路。意图和实际展示结果分开保存。它从获得截图后进入，不测截图轮询召回率。
- `poll` 场景额外运行真实冷却与屏幕哈希逻辑，覆盖快速切换、相同屏幕。硬件、麦克风和 TTS 被隔离。显式问题走原有聊天入口，学习问题保留原有模式。
- 时间来自固定场景时钟。合成图只呈现可见文字；“没有操作”等人类标签不会传给生成器。不能识别的意图不会假装由传感器提供。实际发送的提示、模型原始输出与 token、观察、状态前后、最终决策和文本均保存。
- 这不是实景游戏视觉基准，也不能评价音色、立绘、长期关系或跨天记忆。当前没有的内部状态明确列为 unsupported，不创建装饰性变量。

## 固定评分协议

权重为在场感 25%、人格 20%、连续性 15%、主动自然度 15%、娱乐性 10%、非助手感 10%、克制 5%。各维 0–5 分，转为百分制后加权。裁判必须提供各维证据和有 turn id 的语义问题记录。先按序列和试验分别打分，然后试验等权、序列等权汇总；较长序列和重复受评的中间试验不会被额外加权。

主动发言的六类固定套话按命中发言比例扣非助手感 `2 × 比例`（0–5 量表），主动文本超过 48 字按比例扣克制 `1 × 比例`，最低 0。用户主动求助不适用。问号只是审阅线索，幽默问句不自动处罚。语义层面的建议、复述、强问、空泛鼓励、安慰和虚构由裁判提供证据；避免简单关键字泛化。

全段沉默时在场感、人格、连续性、娱乐性最多 2/5，表示缺少可观察证据；克制和主动自然度仍可高分。沉默既不证明失忆，也不自动证明在场感。不能用少说话刷所有维度。

## 独立与盲法

独立 evaluator 不导入生产生成器或 prompt。裁判看到公开人格卡、事实、场景准则和匿名 A/B 可见输出；看不到模型、版本、试验号、内部状态或生成提示。私有映射仅在汇总时使用。

首次基线只有当前版本：每组比较第 1/2、2/3 次采样，随机左右位置，共 20 对；另 2 对交换位置检查裁判偏差，不计入总分。不能将同版本 A/B 声称为新旧提升。未来比较必须同协议、同场景、同裁判，换新运行目录保存版本指纹；禁止修改已有基线或看完输出再调规则。先冻结协议与 SHA-256，再跑模型。

独立模型裁判仍可能有偏差，需要后续人类盲评校准。导出的 blind-inputs 可以用于人工复核，人工评审前不要查看 private 映射。Assistant-Likeness 风险=100−非助手感，低为好；其余分高为好。Engineering 49 始终单列。

## 预算与保存

最多 126 次生成请求、24 次裁判请求，总 token 停止阈值 450,000（一次正在返回的请求可能越过阈值）；SDK 不自动重试。现有完整场景需要的调用少于上限，因本地静默可零调用。仅评测新增成本，生产运行成本不变。

结果保存在 `docs/character-benchmark/baseline-2026-09-08`：protocol/scenarios/rubric 冻结，screens 合成输入，private/outputs 完整轨迹，blind-inputs 独立裁判输入，judgments 原始裁判输出，summary/REPORT 汇总。生产源码和评测脚本指纹不一致时拒绝混入原基线。
